# Source independence and provenance follow-up v1

18 October 2026. Local deterministic inventory only; no confirmation source was selected, source data redistributed or provider contacted. Prior experiments, splits, labels, grouping manifests and metrics remain unchanged.

The follow-up scanned **2,965 source records** and **1,056,059 normalized evidence words**. For Summary it used the article text, QA the supplied passages, and Data2txt the supplied review text. A first-owner index of exact 20-word shingles produced 176 candidate pairs; deterministic sequence comparison verified **66 pairs sharing at least 40 consecutive normalized words**. Pair IDs, token offsets, shared-token hashes and historical folds are in SOURCE_EXPOSURE_FOLLOWUP.json. Of these, **59** were not already in the same recorded related-source component; **29** cross historical folds. These are review flags, not quantified performance bias or proof that every pair shares one underlying entity/article.

The tokenization is NFKC/casefold plus Unicode word tokens; it differs from the earlier exact numbered-passage normalization, so the reported matching lengths can differ. The positive matches are verified against actual token sequences, not inferred from digest collisions. The first-owner index is a bounded positive-flag discovery method, not exhaustive enumeration of all matching pairs. Shared quotations or copied text may require different interpretation from full-document duplication. No semantic identity, article/URL ownership, within-cluster dependence model or absence of overlap is certified. Fresh-confirmation independence remains unresolved; do not add these rows to an untouched cohort merely because their source IDs differ.

A separate explicit-field scan checked url/source_url/article_url/article_id/passage_id/query_id/business_id/review_id recursively across all local records. **0** records contain a nonempty field in that set. This does not rule out external crosswalks or incidental URLs in free text; it establishes that the needed provider identifiers are not available as those explicit metadata fields here. PROVIDER_METADATA_INVENTORY.json preserves the per-record result without copying article/review text.
